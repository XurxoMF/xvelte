# Input OTP

An accessible segmented input for one-time passwords, verification codes, PINs, and other fixed-length character sequences. It uses one real browser input for typing, pasting, autofill, forms, and keyboard interaction while rendering the current value as locally styled visual cells with an optional blinking caret and separators.

Use Input OTP for short codes sent through an independent channel or generated by an authenticator. Do not use it for permanent passwords, recovery secrets, payment PIN storage, or separate unrelated fields. Treat the value as sensitive, validate it on the server, rate-limit verification attempts, and never rely on visual length or a client-side pattern as proof that a code is valid.

## Import

Import all public parts through the component's `index.ts`:

```svelte
<script lang="ts">
	import * as InputOTP from "$lib/components/ui/input-otp";
</script>
```

`index.ts` exports `Root`, `Group`, `Slot`, and `Separator`, together with their `RootProps`, `GroupProps`, `SlotProps`, and `SeparatorProps` types.

Bits UI's pattern constants are package exports rather than xvelte exports. Import one directly from `bits-ui` only when it is useful to the app:

```ts
import { REGEXP_ONLY_DIGITS, REGEXP_ONLY_CHARS, REGEXP_ONLY_DIGITS_AND_CHARS } from "bits-ui";
```

## Anatomy

Root supplies a required `cells` array through its children snippet. Render every cell exactly once through Slot, normally inside one or more Groups:

```svelte
<InputOTP.Root maxlength={6}>
	{#snippet children({ cells })}
		<InputOTP.Group>
			{#each cells.slice(0, 3) as cell (cell)}
				<InputOTP.Slot {cell} />
			{/each}
		</InputOTP.Group>

		<InputOTP.Separator aria-hidden="true" />

		<InputOTP.Group>
			{#each cells.slice(3, 6) as cell (cell)}
				<InputOTP.Slot {cell} />
			{/each}
		</InputOTP.Group>
	{/snippet}
</InputOTP.Root>
```

The rendered structure is conceptually:

```text
Bits UI Root container
├── Group
│   ├── Slot
│   ├── Slot
│   └── Slot
├── Separator
├── Group
│   ├── Slot
│   ├── Slot
│   └── Slot
└── Absolute input wrapper
    └── Real transparent input
```

The visual Slots are not independent form controls. Bits UI stretches one transparent native input over the visual content, manages its selection, and derives `cell.char`, `cell.isActive`, and `cell.hasFakeCaret` for each Slot.

## Basic usage

Give the real input an ID through `inputId`, associate a visible label with it, and constrain the accepted characters explicitly:

```svelte
<script lang="ts">
	import * as InputOTP from "$lib/components/ui/input-otp";

	let code = $state("");
</script>

<div class="grid gap-2">
	<label for="verification-code" class="text-sm font-medium">Verification code</label>

	<InputOTP.Root
		inputId="verification-code"
		name="verificationCode"
		maxlength={6}
		pattern="^[0-9]+$"
		inputmode="numeric"
		autocomplete="one-time-code"
		bind:value={code}
	>
		{#snippet children({ cells })}
			<InputOTP.Group>
				{#each cells as cell (cell)}
					<InputOTP.Slot {cell} />
				{/each}
			</InputOTP.Group>
		{/snippet}
	</InputOTP.Root>
</div>
```

`maxlength` determines both the accepted value length and the number of generated cells. It is required by the installed public type even though Bits UI has an internal runtime fallback of `6`.

`inputmode="numeric"` only requests a numeric-oriented keyboard; it does not reject letters from a physical keyboard or paste. Use `pattern` when the value must contain only a specific character set.

## Examples

### Split groups and custom separator

Groups define where adjacent borders join. Separator accepts custom children when a visual hyphen is not appropriate:

```svelte
<InputOTP.Root maxlength={8} pattern="^[A-Z0-9]+$" inputmode="text">
	{#snippet children({ cells })}
		<InputOTP.Group>
			{#each cells.slice(0, 4) as cell (cell)}
				<InputOTP.Slot {cell} />
			{/each}
		</InputOTP.Group>

		<InputOTP.Separator aria-hidden="true">
			<span class="px-1">/</span>
		</InputOTP.Separator>

		<InputOTP.Group>
			{#each cells.slice(4) as cell (cell)}
				<InputOTP.Slot {cell} />
			{/each}
		</InputOTP.Group>
	{/snippet}
</InputOTP.Root>
```

The pattern is a JavaScript regular-expression source used during keyboard and paste handling. It does not transform lowercase input to uppercase; perform that transformation through controlled state or a suitable paste transformer when required.

### Transform pasted codes

Remove formatting characters before Bits UI validates and inserts pasted text:

```svelte
<InputOTP.Root maxlength={6} pattern="^[0-9]+$" pasteTransformer={(text) => text.replace(/[\s-]/g, "")}>
	{#snippet children({ cells })}
		<InputOTP.Group>
			{#each cells as cell (cell)}
				<InputOTP.Slot {cell} />
			{/each}
		</InputOTP.Group>
	{/snippet}
</InputOTP.Root>
```

The transformer receives clipboard text and must return the complete sanitized string. The result is still capped to `maxlength` and checked against `pattern`.

### Completion callback

`onComplete` runs when a previously incomplete value reaches exactly `maxlength`:

```svelte
<script lang="ts">
	import * as InputOTP from "$lib/components/ui/input-otp";

	let code = $state("");
	let verifying = $state(false);
	let error = $state("");

	async function verify(completedCode: string) {
		verifying = true;
		error = "";

		try {
			await verifyCode(completedCode);
		} catch {
			error = "The code could not be verified.";
		} finally {
			verifying = false;
		}
	}
</script>

<InputOTP.Root
	maxlength={6}
	pattern="^[0-9]+$"
	bind:value={code}
	disabled={verifying}
	onComplete={(completedCode) => {
		void verify(completedCode);
	}}
>
	{#snippet children({ cells })}
		<InputOTP.Group>
			{#each cells as cell (cell)}
				<InputOTP.Slot {cell} />
			{/each}
		</InputOTP.Group>
	{/snippet}
</InputOTP.Root>

{#if error}
	<p role="alert">{error}</p>
{/if}
```

Bits UI does not await a returned promise or add a loading state. `onComplete` does not fire merely because Root mounts with an already complete value, and replacing one complete value with another does not retrigger it until the value first becomes shorter than `maxlength`.

Do not log, render, or announce the completed code unless the workflow genuinely requires it.

### Native form submission

Native input attributes such as `name`, `required`, and `form` apply to the real transparent input:

```svelte
<form method="POST" class="grid gap-3">
	<label for="mfa-code">Authentication code</label>
	<p id="mfa-help">Enter the six-digit code from your authenticator app.</p>

	<InputOTP.Root inputId="mfa-code" name="mfaCode" maxlength={6} pattern="^[0-9]+$" required aria-describedby="mfa-help">
		{#snippet children({ cells })}
			<InputOTP.Group>
				{#each cells as cell (cell)}
					<InputOTP.Slot {cell} />
				{/each}
			</InputOTP.Group>
		{/snippet}
	</InputOTP.Root>

	<button type="submit">Verify</button>
</form>
```

Client-side completion and pattern checks are usability features. The server must verify the code, expiry, intended account/session, attempt count, and replay policy.

### Invalid visual state

Root forwards `aria-invalid` to the real input for assistive technology. The local Group and Slot invalid styles inspect their own visual descendants, so pass the same state to Slot as well:

```svelte
<script lang="ts">
	let invalid = $state(true);
</script>

<InputOTP.Root maxlength={6} aria-invalid={invalid} aria-describedby="code-error">
	{#snippet children({ cells })}
		<InputOTP.Group>
			{#each cells as cell (cell)}
				<InputOTP.Slot {cell} aria-invalid={invalid} />
			{/each}
		</InputOTP.Group>
	{/snippet}
</InputOTP.Root>

<p id="code-error" class="text-sm text-destructive">The code has expired. Request a new one.</p>
```

Setting `aria-invalid` only on Root does not activate Group's `has-aria-invalid` selector because the real input is a sibling of the visual Group, not its descendant.

## Public API

Input OTP wraps the installed stable Bits UI Pin Input primitive. The tables document every local adaptation and the inherited options most relevant to ordinary use; see the [Bits UI Pin Input API](https://bits-ui.com/docs/components/pin-input) for the complete primitive API. Input OTP's `index.ts`, exported types, and local source are the source of truth.

### `InputOTP.Root`

Type: `RootProps`, equal to Bits UI's `PinInput.RootProps`.

| Prop                          | Type                                          | Default            | Behavior                                                                                         |
| ----------------------------- | --------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------ |
| `maxlength`                   | `number`                                      | Required by type   | Controls accepted length and the number of generated `cells`. Installed runtime fallback: `6`.   |
| `value`                       | `string`                                      | `""`               | Bindable complete input value.                                                                   |
| `onValueChange`               | `(value: string) => void`                     | `undefined`        | Runs when Bits UI changes the value.                                                             |
| `onComplete`                  | `(value: string) => void`                     | `undefined`        | Runs when an incomplete value first reaches exactly `maxlength`.                                 |
| `pasteTransformer`            | `(text: string) => string`                    | `undefined`        | Sanitizes clipboard text before insertion and pattern validation.                                |
| `pattern`                     | `string`                                      | `undefined`        | Regular-expression source used to reject invalid typing and pasted values.                       |
| `inputmode`                   | Native input-mode value                       | `"numeric"`        | Requests an appropriate virtual keyboard without itself restricting characters.                  |
| `autocomplete`                | Native autocomplete value                     | `"one-time-code"`  | Configures browser and platform one-time-code autofill.                                          |
| `textalign`                   | `"left" \| "center" \| "right"`               | `"left"`           | Aligns the transparent input text and affects long-press/selection behavior.                     |
| `disabled`                    | `boolean`                                     | `false`            | Disables the real input and activates Root's descendant-disabled opacity.                        |
| `pushPasswordManagerStrategy` | `"increase-width" \| "none"`                  | `"increase-width"` | Optionally widens/clips the real input to move password-manager badges outside the visual cells. |
| `inputId`                     | `string`                                      | Generated          | ID applied to the real input; use it as a label's `for` value.                                   |
| `inputRef`                    | `HTMLInputElement \| null`                    | `null`             | Bindable reference to the real transparent input.                                                |
| `ref`                         | `HTMLElement \| null`                         | `null`             | Bindable reference to Bits UI's outer Root container.                                            |
| `children`                    | `Snippet<[{ cells, isFocused, isHovering }]>` | Required           | Renders the visual Groups, Slots, and Separators from reactive primitive state.                  |
| `class`                       | `string`                                      | `undefined`        | Merged onto the outer Root container after its local layout and disabled-state classes.          |

Native input props such as `name`, `form`, `required`, `readonly`, `aria-*`, event handlers, and related attributes are forwarded to the real input according to Bits UI's prop-merging behavior. Root locally supplies `spellcheck={false}` and `data-slot="input-otp"`; both reach the real input rather than the outer container. A forwarded conflicting value can replace either local default.

The children snippet receives:

| Field        | Type             | Meaning                                                             |
| ------------ | ---------------- | ------------------------------------------------------------------- |
| `cells`      | `PinInputCell[]` | One reactive descriptor per index from `0` through `maxlength - 1`. |
| `isFocused`  | `boolean`        | Whether the real input currently has focus.                         |
| `isHovering` | `boolean`        | Whether the pointer is over the real input overlay.                 |

The underlying `PinInputCell` type is supplied by Bits UI through Slot's public `cell` prop; xvelte does not re-export the standalone type.

### `InputOTP.Group`

Type: `GroupProps`, based on native `HTMLAttributes<HTMLDivElement>` with a bindable reference.

| Prop       | Type                  | Default     | Behavior                                                               |
| ---------- | --------------------- | ----------- | ---------------------------------------------------------------------- |
| `ref`      | `HTMLElement \| null` | `null`      | Bindable rendered Group reference.                                     |
| `children` | `Snippet`             | `undefined` | Renders adjacent Slots.                                                |
| `class`    | `string`              | `undefined` | Merged after flex, radius, descendant-invalid border, and ring styles. |

Group renders `data-slot="input-otp-group"` before forwarding native props. Do not replace this stable hook. It does not add a role, label, value, orientation, or state of its own.

Group becomes invalid only when one of its descendants carries `aria-invalid`. Root's real input is outside Group, so Root-level invalid state alone is insufficient for this local visual rule.

### `InputOTP.Slot`

Type: `SlotProps`, equal to Bits UI's `PinInput.CellProps`.

| Prop           | Type                  | Default     | Behavior                                                                                               |
| -------------- | --------------------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| `cell`         | `PinInputCell`        | Required    | Reactive descriptor supplying `char`, `isActive`, and `hasFakeCaret`.                                  |
| `ref`          | `HTMLElement \| null` | `null`      | Bindable rendered visual cell reference.                                                               |
| `class`        | `string`              | `undefined` | Merged after the local dimensions, connected borders, radius, active, invalid, dark, and caret layout. |
| `aria-invalid` | ARIA boolean          | `undefined` | Activates local destructive cell styling and Group's descendant-invalid styling.                       |
| `child`        | Bits UI child snippet | `undefined` | Delegates the Cell element; the custom element must spread every supplied primitive prop.              |

In normal composition Slot always renders `cell.char` and, when `cell.hasFakeCaret` is true, the local blinking caret. A delegated `child` replaces Bits UI's default Cell branch and therefore bypasses that normal local visual content; recreate the character and caret deliberately if using this advanced inherited option.

Bits UI supplies `data-active`, `data-inactive`, and `data-pin-input-cell`. The local wrapper adds `data-slot="input-otp-slot"`. Forwarded props are applied after the slot value and can replace it; preserve the documented hook.

### `InputOTP.Separator`

Type: `SeparatorProps`, based on native `HTMLAttributes<HTMLDivElement>` with a bindable reference.

| Prop       | Type                  | Default     | Behavior                                                                       |
| ---------- | --------------------- | ----------- | ------------------------------------------------------------------------------ |
| `ref`      | `HTMLElement \| null` | `null`      | Bindable rendered separator reference.                                         |
| `children` | `Snippet`             | `undefined` | Replaces the default semantic `MinusIcon` when supplied.                       |
| `class`    | `string`              | `undefined` | Merged after flex alignment and the default size selector for descendant SVGs. |

Separator renders a `div` with `role="separator"` and `data-slot="input-otp-separator"`. Native props are forwarded last and can replace them. Add `aria-hidden="true"` when the divider is purely visual and conveys no useful grouping to assistive technology.

The default MinusIcon comes from the shared xvelte icon facade. It receives a `1rem` size unless it already has a `size-*` class.

## Styling and DOM contract

The component combines xvelte hooks with Bits UI's generated structure:

| Part                 | Stable local hook                 | Default element |
| -------------------- | --------------------------------- | --------------- |
| Root's real input    | `data-slot="input-otp"`           | Native `input`  |
| Group                | `data-slot="input-otp-group"`     | Native `div`    |
| Slot                 | `data-slot="input-otp-slot"`      | Native `div`    |
| Separator            | `data-slot="input-otp-separator"` | Native `div`    |
| Root outer container | No local `data-slot`              | Native `div`    |
| Fake-caret wrapper   | No local `data-slot`              | Native `div`    |

Root's class is applied to the outer Bits UI container, while native input attributes and `data-slot="input-otp"` are applied to the transparent input. Do not assume that the slot and Root's layout classes share the same DOM element.

Group lays Slots in a row. Each Slot is a `2rem` square with connected semantic input borders: top, bottom, and end borders on every cell; an additional start border and start radius on the first cell; and an end radius on the last cell.

An active Slot receives `z-10`, a semantic ring border, and a three-pixel focus ring. Invalid Slots use destructive border/ring colors. Dark mode adds an input-tinted Slot background.

The local fake caret is an absolute, pointer-transparent overlay. Its inner one-pixel line uses `animate-caret-blink`, `bg-foreground`, and `duration-1000`; `tw-animate-css` supplies the animation and caret keyframes.

Bits UI owns additional implementation details, including:

- `data-pin-input-root`, `data-pin-input-input`, `data-pin-input-cell`, active/inactive attributes, selection metadata, and generated IDs.
- Absolute input-wrapper and input positioning, transparent text/caret, selection mirroring, keyboard/paste filtering, and password-manager badge handling.
- The `--bits-pin-input-root-height` variable, updated from the real input by `ResizeObserver`.
- A document-level `<style id="pin-input-style">` injected once for autofill, selection, iOS, and password-manager behavior.

All local parts with a `class` prop merge through `cn`, allowing later conflicting Tailwind utilities to replace ordinary defaults. High-specificity state, first/last, descendant, ARIA, and data-attribute selectors may require equally specific overrides.

## Accessibility

Bits UI presents one real native input instead of several independent one-character fields. This preserves ordinary typing, selection, paste, mobile keyboards, browser one-time-code autofill, form submission, focus, and screen-reader interaction while the visual cells mirror the value.

App responsibilities:

- Give the real input an accessible name. Prefer a visible label whose `for` matches Root's `inputId`; otherwise provide a valid `aria-label` or `aria-labelledby` on Root.
- Keep instructions and errors outside the visual cells and connect them to Root with `aria-describedby`.
- Use `autocomplete="one-time-code"` for actual verification codes. Do not use autocomplete tokens that misrepresent the data.
- Use `inputmode` to improve virtual keyboards and `pattern` to filter characters, but never substitute either for server validation.
- Mark Root `aria-invalid` for the real control and mirror the state to Slots when local invalid visuals are required.
- Hide decorative Separators from assistive technology. Their visual grouping does not change the single-input value or reading model.
- Preserve the active-cell ring and fake caret, or provide an equally clear focus and insertion indication.
- Do not render the current code in a live region, log, analytics event, toast, URL, or other unnecessary surface.
- Keep a visible submit/verify action unless the workflow has a clearly communicated and recoverable auto-submit behavior.
- Announce asynchronous errors or success appropriately and return focus deliberately when a new code must be entered.

The local caret animation does not include a reduced-motion override. Disable or replace it for people requesting reduced motion when a continuous blink is undesirable.

Disabled Root disables the real input and dims the complete outer container through `has-disabled:opacity-50`; visual Slots are generic elements and are not individually disabled.

## Localization

Input OTP has no built-in user-facing copy and imports no localization messages. The app supplies and translates labels, delivery-channel descriptions, resend instructions, expiry messages, errors, loading states, action labels, and recovery guidance.

The browser or operating system owns one-time-code autofill prompts and virtual keyboard presentation. Input mode, autocomplete, pattern, `data-*`, and form values are technical identifiers and are not translated.

## Dependencies

Input OTP expects a Svelte 5 project using Tailwind CSS 4. It requires Bits UI's Pin Input primitive, the Tabler minus icon through the shared xvelte icon facade, shared utility helpers, and `tw-animate-css` for the fake caret.

Install every runtime dependency first and development dependencies second:

```sh
# bun
bun add bits-ui @tabler/icons-svelte clsx tailwind-merge
bun add -D tailwindcss tw-animate-css

# npm
npm install bits-ui @tabler/icons-svelte clsx tailwind-merge
npm install -D tailwindcss tw-animate-css

# pnpm
pnpm add bits-ui @tabler/icons-svelte clsx tailwind-merge
pnpm add -D tailwindcss tw-animate-css
```

### Component files

Copy the complete `src/lib/components/ui/input-otp` component folder:

- `input-otp-root.svelte`
- `input-otp-group.svelte`
- `input-otp-slot.svelte`
- `input-otp-separator.svelte`
- `index.ts`
- `README.md`

No other xvelte UI component, context module, hook, attachment, standalone helper file, shared component stylesheet, image, font, or network service is required.

### Shared utilities

Input OTP imports `cn` and `WithElementRef` from `$lib/utils`. Add these exact definitions to `src/lib/utils.ts` when absent:

```ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

/**
 * Merges class values and resolves conflicting Tailwind utilities in favor of the last value.
 *
 * @param inputs - Conditional, nested, or plain class values to merge.
 * @returns The normalized class string.
 */
export function cn(...inputs: ClassValue[]) {
	return twMerge(clsx(inputs));
}

export type WithElementRef<T, U extends HTMLElement = HTMLElement> = T & {
	ref?: U | null | undefined;
};
```

The package block includes `clsx` and `tailwind-merge`, which `cn` imports.

### Icon

Separator imports the semantic `MinusIcon` name from `$lib/icons`. Add this exact export to `src/lib/icons.ts`:

```ts
export { default as MinusIcon } from "@tabler/icons-svelte/icons/minus";
```

The package block includes `@tabler/icons-svelte`. Keep this semantic alias in the shared icon facade instead of importing Tabler directly from the component.

### Global CSS

The global stylesheet must load Tailwind and `tw-animate-css`, define the dark variant, and expose the semantic colors and radius used by Input OTP. These are xvelte's defaults; apps may replace the values while preserving their names and mappings:

```css
@import "tailwindcss";
@import "tw-animate-css";

@custom-variant dark (&:is(.dark *));

:root {
	--foreground: oklch(0.147 0.004 49.25);
	--destructive: oklch(0.577 0.245 27.325);
	--input: oklch(0.923 0.003 48.717);
	--ring: oklch(0.709 0.01 56.259);
	--radius: 0.45rem;
}

.dark {
	--foreground: oklch(0.985 0.001 106.423);
	--destructive: oklch(0.704 0.191 22.216);
	--input: oklch(1 0 0 / 15%);
	--ring: oklch(0.553 0.013 58.071);
}

@theme inline {
	--color-foreground: var(--foreground);
	--color-destructive: var(--destructive);
	--color-input: var(--input);
	--color-ring: var(--ring);
	--radius-lg: var(--radius);
}
```

`tw-animate-css` provides `animate-caret-blink` and its caret keyframes; the local `duration-1000` class sets the animation duration. The app owns dark-mode activation.

Input OTP requires no base-layer rule, custom data-state variant, additional keyframe, localization message, or layout CSS. Bits UI injects its own required runtime styles for the transparent input as described in [Styling and DOM contract](#styling-and-dom-contract).

| `input-otp-root.svelte`      | Bindable value/root reference, local Root classes and input defaults, and forwarding to the Bits UI Pin Input root.        |
