# Label

An accessible text label for identifying a form control. It renders a native `label` by default, supports explicit association through `for`, implicit association by wrapping a control, forwards the Bits UI Label API, and includes consistent typography and disabled-state styling hooks.

Use Label for inputs, checkboxes, radio controls, selects, textareas, and other labelable controls. Do not use it as ordinary body text, a section heading, placeholder text, or the only explanation of a validation error.

## Import

Import the component through its public `index.ts` entry point:

```svelte
<script lang="ts">
	import * as Label from "$lib/components/ui/label";
</script>
```

Label's `index.ts` exports `Root` and the `RootProps` type.

---

## Anatomy

Associate Label and a control by matching the label's `for` with the control's `id`:

```svelte
<Label.Root for="email">Email address</Label.Root>
<input id="email" name="email" type="email" />
```

The component renders a native `label` unless the inherited `child` snippet replaces it. Label does not render a control, description, required marker, validation message, or surrounding field layout.

---

## Basic usage

```svelte
<script lang="ts">
	import * as Label from "$lib/components/ui/label";
</script>

<div class="grid gap-2">
	<Label.Root for="display-name">Display name</Label.Root>
	<input id="display-name" name="displayName" autocomplete="name" />
</div>
```

Clicking the label focuses or activates its associated control through native browser behavior.

## Examples

### Wrap a native control

A native label can contain its control instead of using `for` and `id`:

```svelte
<Label.Root>
	<input name="terms" type="checkbox" />
	Accept the terms and conditions
</Label.Root>
```

Use either explicit or implicit association. Explicit `for`/`id` pairing is usually clearer when the label and control need separate layout wrappers.

### Disabled control with peer styling

The local disabled classes react when a preceding sibling control has both the native `disabled` attribute and Tailwind's `peer` class:

```svelte
<div class="flex items-center gap-2">
	<input id="archived" class="peer" type="checkbox" disabled />
	<Label.Root for="archived">Archived records</Label.Root>
</div>
```

This makes the label use a not-allowed cursor and reduced opacity. Label itself has no `disabled` prop and does not disable the associated control.

### Disabled group styling

An ancestor can disable pointer events and reduce label opacity with the generic group hook:

```svelte
<div class="group grid gap-2" data-disabled="true">
	<Label.Root for="workspace">Workspace</Label.Root>
	<input id="workspace" name="workspace" disabled />
</div>
```

Set the control's actual disabled state as well. `data-disabled` only activates styling and pointer-event rules on the label.

### Required and optional copy

```svelte
<Label.Root for="organization">
	Organization <span aria-hidden="true">*</span>
</Label.Root>
<input id="organization" name="organization" required aria-required="true" />

<Label.Root for="nickname">
	Nickname <span class="font-normal">(optional)</span>
</Label.Root>
<input id="nickname" name="nickname" />
```

Keep the control's native `required` state authoritative. A visual marker alone does not communicate the requirement to every user.

## Public API

Type: `RootProps`, an alias of `LabelPrimitive.RootProps`. Label forwards the Bits UI primitive API and native label attributes. The component's `index.ts`, exported type, and installed stable Bits UI version are the source of truth.

| Prop       | Type                                            | Default              | xvelte behavior                                                                                                                    |
| ---------- | ----------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `for`      | `string`                                        | `undefined`          | Associates the native label with the control whose `id` matches this value.                                                        |
| `id`       | `string`                                        | Generated by Bits UI | Identifies the label itself. It does not replace the control association provided by `for`.                                        |
| `children` | `Snippet`                                       | `undefined`          | Renders the label's visible content.                                                                                               |
| `child`    | `Snippet<[{ props: Record<string, unknown> }]>` | `undefined`          | Replaces the native label through render delegation. Spread every supplied prop onto the rendered element.                         |
| `ref`      | `HTMLElement \| null`                           | `null`               | Bindable reference to the default label or delegated element. Bits UI keeps the type broad because `child` may change the element. |
| `class`    | `string`                                        | `undefined`          | Merged after the local layout, typography, selection, and disabled-state classes.                                                  |

Other native label attributes and event handlers are forwarded. Bits UI composes an internal mouse handler that prevents repeated clicks from selecting the label text.

See the [Bits UI Label API reference](https://www.bits-ui.com/docs/components/label#api-reference) for the complete inherited primitive API. The local wrapper adds styling and `data-slot="label"` but does not remove any primitive prop.

### Render delegation

The `child` snippet receives a `props` object containing the merged native attributes, generated ID, Bits UI data attribute, mouse behavior, and local class and slot values:

```svelte
<Label.Root for="search">
	{#snippet child({ props })}
		<label {...props}>Search query</label>
	{/snippet}
</Label.Root>
```

Use the default rendering unless delegation is genuinely needed. Rendering a non-label element removes the native `for` association unless the replacement provides equivalent accessible behavior.

## Styling and DOM contract

Stable xvelte hooks:

| Element    | Attribute           | Source  |
| ---------- | ------------------- | ------- |
| Label root | `data-slot="label"` | xvelte  |
| Label root | `data-label-root`   | Bits UI |

The default label is an inline-width flex container with centered children, a small gap, compact line height, medium-weight text, and disabled text selection.

Disabled styling has two independent triggers:

- `peer-disabled:*` activates when a disabled element with the `peer` class precedes Label in a compatible sibling structure.
- `group-data-[disabled=true]:*` activates when a compatible ancestor has the `group` class and `data-disabled="true"`.

The peer path adds a not-allowed cursor and reduced opacity. The group path adds reduced opacity and disables pointer events. These selectors only style Label; they do not derive, set, or forward a disabled state.

The public `class` is merged with the local classes through `cn()`, so later conflicting Tailwind utilities normally win. When `child` is used, the class and both data attributes move to the delegated element if its snippet spreads `props`.

## Accessibility

Bits UI preserves native label semantics and prevents unwanted text selection during repeated clicking. The browser owns focus and activation of the associated control.

- Match `for` to one unique control `id`, or wrap the control inside Label.
- Every form control should have a concise label that describes the requested value or choice. Placeholder text is not a replacement.
- Keep visible label text whenever possible. Use `aria-label` or `aria-labelledby` on the control only when a visible Label is genuinely unsuitable.
- A label may contain text, icons, and its associated control, but avoid unrelated buttons, links, or additional interactive controls inside it because clicking them can create ambiguous activation behavior.
- Label has no disabled semantic state. Apply `disabled` to the actual control; use peer or group hooks only to mirror that state visually.
- Required markers, help text, and errors need their own semantics. Apply `required` or `aria-required` to the control and connect descriptions or errors with the appropriate ARIA attributes.
- When using `child`, preserve a native label whenever possible and spread every supplied prop.

## Localization

Label has no built-in user-facing copy and imports no localization messages. Your app supplies and translates label text, required or optional indicators, units, instructions, descriptions, and validation messages.

The `for`, `id`, `data-slot`, and Bits UI data attributes are technical identifiers and are not translated. Keep translated label wording concise while preserving the meaning of the associated control.

## Dependencies

Label expects a Svelte 5 project using Tailwind CSS 4. Install Bits UI and the class-merging packages as runtime dependencies, then Tailwind as a development dependency:

```sh
# bun
bun add bits-ui clsx tailwind-merge
bun add -D tailwindcss

# npm
npm install bits-ui clsx tailwind-merge
npm install -D tailwindcss

# pnpm
pnpm add bits-ui clsx tailwind-merge
pnpm add -D tailwindcss
```

### Component files

Copy the complete `src/lib/components/ui/label` component folder:

- `label-root.svelte`
- `index.ts`
- `README.md`

Inputs, checkboxes, fields, descriptions, and errors shown with Label are optional compositions. Copy each additional xvelte component and follow its README only when using it.

### Shared utilities

Root imports only `cn` from `$lib/utils`. Add this exact definition to `src/lib/utils.ts` when absent:

```ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

/**
 * Merges class values and resolves conflicting Tailwind utilities in favor of the last value.
 *
 * @param inputs - Conditional, nested, or plain class values to merge.
 * @returns The normalized class string.
 */
export function cn(...inputs: ClassValue[]) {
	return twMerge(clsx(inputs));
}
```

The package installation block includes `clsx` and `tailwind-merge`.

### Global CSS

Label's local styles use Tailwind utilities without semantic color variables, dark-mode selectors, animations, or shared radius values. The only required global stylesheet code is the Tailwind import:

```css
@import "tailwindcss";
```

Label requires no `tw-animate-css` import, semantic CSS variable, `@theme` mapping, base-layer rule, keyframe, icon export from `src/lib/icons.ts`, localization message, other xvelte component, hook, attachment, context, image, font, network service, or additional layout rule.
